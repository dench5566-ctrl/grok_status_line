# Строка состояния Grok

Нижняя строка в терминале Grok на macOS.
Она показывает модель, папку, остаток окна разговора и остаток лимита аккаунта.

Инструмент строки — файл `statusline.py` в этом репозитории.
Ставит его на компьютер скрипт `install.py`.

Старый репозиторий [grok-build-statusline](https://github.com/dench5566-ctrl/grok-build-statusline) этой полоски лимита не содержит.
Брать скрипт нужно отсюда.

## Для вас

Строка из двух линий. Пример:

```
◆ Grok 4.7·xhigh │ step2life_v5 (main) │ ctx 150k/200k 75% │ week: 67% (03 okt) ▰▰▰▰▰▰▰▱▱▱
ctx ▰▰▰▰▰▰▰▰▱▱ 75%
```

### Лимит аккаунта

Кусок `week: 67% (03 okt)` и полоска рядом с ним — это лимит аккаунта.

- `week` значит, что окно лимита — неделя. Если окно станет месяцем, слово сменится на `month`.
- `67%` — сколько осталось.
- `(03 okt)` — день, когда окно обновится. Октябрь написан `okt`.
- Полоска — тоже остаток. Закрашенная часть — это остаток. Пустая часть уже израсходована.
- Чем короче полоска, тем меньше осталось.

Цвет синий, когда остатка много.
К оранжевому он переходит, когда израсходовано от 70%.
К красному — когда израсходовано от 90%.

Число лимита обновляется примерно раз в минуту.
Остальная строка обновляется чаще.

### Окно разговора

`ctx 150k/200k 75%` — сколько ещё влезает в текущий разговор.
Первое число — остаток. Второе — размер окна. Процент — тоже остаток.

Полоска `ctx` на второй линии — то же окно разговора.
Чем она короче, тем меньше места осталось в разговоре.
Это не лимит аккаунта.

### Остальные знаки

- `◆ Grok 4.7·xhigh` — модель и уровень рассуждения.
- `step2life_v5 (main)` — папка и ветка git. Звёздочка у ветки значит, что в папке есть несохранённые правки.
- `$1.20` — стоимость этой сессии, если она уже посчитана.
- `2м` — сколько длится сессия.
- `in` — сколько токенов ушло на вход за сессию.
- `cache` — какая доля входа взята из кэша.
- `compact` — порог, после которого разговор сжимается.
- `turn` — сколько длится текущий ответ.

На экране приветствия строки нет.
Её нет и в полноэкранном виде вложенного агента.

### Что сделать вам

Войти в Grok на этом Mac командой `grok login`, если вход ещё не сделан.
Дальше строку ставит ИИ из следующего раздела, командой `python3 install.py`.

Если блок лимита пустой, вход в Grok протух.
Снова выполните `grok login`.
Число появится в течение минуты.

Пароль и ключ входа в эту инструкцию и в репозиторий не входят.
Они лежат только в `~/.grok/auth.json` на вашем Mac.

## Для ИИ

Поставить эту строку на macOS человеку, у которого уже есть Grok Build.
Скрипт не переписывать.
Формат лимита не менять.
Полоску не переворачивать.

### Инструменты в этом репозитории

- `statusline.py` — сама строка. Копировать целиком.
- `install.py` — кладёт скрипт в `~/.grok/statusline.py` и записывает только таблицу `[ui.status_line]` в `~/.grok/config.toml`.

Другие ключи `config.toml` не менять.
Файл `~/.grok/auth.json` не печатать, не копировать и не коммитить.
Файл `~/.grok/statusline-billing.json` — кэш процентов. В репозиторий его не класть.

### Команды

Из корня этого репозитория:

```sh
python3 install.py
```

Скрипт ставится так:

```toml
[ui.status_line]
type = "command"
command = "/usr/bin/python3 ~/.grok/statusline.py"
padding = 0
refresh_interval = 10
```

Правка `statusline.py` видна на следующем обновлении строки.
Новый запуск Grok для этого не нужен.
Правка `config.toml` читается при старте Grok.
После первой записи блока Grok нужно открыть заново.

### Проверка

Подставить любой JSON и посмотреть текст без цвета:

```sh
printf '%s' '{"trigger":"state","model":{"display_name":"Grok 4.7"},"workspace":{"current_dir":"/tmp"},"context_window":{"context_window_size":200000,"context_tokens":50000,"used_percentage":25,"remaining_percentage":75}}' \
  | /usr/bin/python3 ~/.grok/statusline.py \
  | sed $'s/\x1b\\[[0-9;]*m//g'
```

В первой линии должен быть кусок вида `week: 67% (03 okt)` и полоска из символов `▰` и `▱`.
Число — остаток, не расход.
Закрашенных `▰` столько, сколько осталось.
Если остаток маленький, закрашенная часть короткая.

Пока кэша нет, эта команда один раз сходит в сеть за лимитом.
Повтор в ту же минуту читает `~/.grok/statusline-billing.json`.

### Откуда берётся лимит

Во входном JSON Grok поля лимита аккаунта нет.
Скрипт сам запрашивает `https://cli-chat-proxy.grok.com/v1/billing?format=credits`.
Берёт ключ `key` из `~/.grok/auth.json` и шлёт его как `Authorization: Bearer`.
Из ответа читает `config.creditUsagePercent`.
Это расход. На экран выводится `100` минус это число.

Кэш живёт 60 секунд.
Пока идёт ответ модели, Grok зовёт скрипт с `"trigger": "state"`.
В этом режиме сеть не трогать, если кэш уже есть.
Сеть допустима при `"trigger": "refresh_interval"` и когда кэша ещё нет.

Если запрос не удался, оставить прошлое число.
Остальную строку всё равно напечатать.

### Что нельзя менять в виде

- Текст лимита: `week: 67% (03 okt)`. Процент — остаток. Дата — местный день обновления окна. Месяцы: `jan feb mar apr may jun jul aug sep okt nov dec`.
- Полоска лимита и полоска `ctx` закрашивают остаток.
- Чем короче полоска, тем меньше осталось.
- Окно разговора на экране тоже остаток: `ctx остаток/размер процент`.
- Вторая линия не повторяет лимит недели.

### Чего скрипт не делает

Он не ставит Grok.
Он не выполняет `grok login`.
Он не читает чужой аккаунт.
Он не пишет ключ входа в вывод и в кэш.
В кэше только процент расхода, тип окна, дата конца окна и время запроса.
